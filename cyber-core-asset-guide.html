Cyber-Breach: Data Core 에셋 작업 가이드

에셋 담당자가 바로 읽고 써먹게 만든 정리본. 맨 위에는 공통 프롬프트, 그다음에 적용 대상, 초안 뽑는 팁, 바이브 코딩용 에셋 제작 흐름, 참고 사이트 순서로 넣었다.

탑다운 3/4 시점 2D 서바이버라이크 사이버 침투 세계관 48~64px 가독성 우선 실루엣 구분 최우선

1. 공통 프롬프트

기본 공통 프롬프트
Create a production-ready 2D game asset concept sheet for [SUBJECT].

Top-down three-quarter view, cyber intrusion survivorlike game, bold readable silhouette, minimal geometric cyberpunk design, clean vector-like rendering, controlled neon glow, dark internal shadows, no text, no logo, no UI frame.

Show:
1. idle sprite,
2. movement pose,
3. attack pose,
4. damaged pose,
5. simplified minimap icon.

The asset must remain recognizable at 48–64 pixels.
Use clear shape language and avoid excessive tiny details.
Neutral transparent background, evenly spaced concept sheet.
플레이어/침투 진영 추가 문장
Intruder faction design language: asymmetrical triangular forms, saturated magenta, violet or lime accents, flowing glitch trails, fast agile appearance.
적/보안 진영 추가 문장
Security faction design language: rigid symmetry, white and pale cyan armor, square and shield-based construction, hostile orange warning lights.
노드용 추가 문장
Shared node structure: hexagonal floor platform, neutral gunmetal chassis, circular capture boundary, central holographic device, clear top-down readability.
무기/VFX용 추가 문장
Focus on projectile shape, trail, impact effect, and attack readability rather than character detail. Keep the silhouette readable even when scaled small.

2. 적용 대상

레포 기준으로 지금 구분해서 작업해야 할 대상들. 한 번에 다 하지 말고, 아래 우선순위로 나눠서 가는 게 맞다.

분류수량우선 작업 포인트
플레이어 프로그램3게임의 정체성. 먼저 뽑아서 전체 스타일 앵커로 삼기
일반/엘리트 적12실루엣 충돌 방지. 빠른놈/원거리/방패형이 즉시 구분돼야 함
보스4화면 장악감, 약점 위치, 공격 방향 읽힘이 핵심
보안 노드7공통 기단 + 중앙 심볼만 바꿔서 통일감 유지
기본 무기18투사체, 장판, 빔, 소환체, 디버프 마커를 분리해서 설계
진화 무기12기본 무기의 상위 형태처럼 보여야 함
바이옴4배경·타일·오브젝트 세트로 묶기
UI/HUD1세트체력·경험치·해킹 게이지·보스바·아이콘 통일
작업 순서 추천: 플레이어 3종 → 기본 적 4~6종 → 노드 7종 → 핵심 무기/VFX → 보스 4종 → 바이옴 → UI. 이유는 간단함. 먼저 움직이는 애들이 읽혀야 테스트가 돌아가고, 그다음 목표물과 공격 이펙트를 붙이면 게임 맛이 산다.

3. 이미지 초안 에셋으로 뽑는 팁

3-1. 포스터 말고 “콘셉트 시트”

  • idle / move / attack / damaged / minimap icon을 같이 뽑기
  • 배경은 투명 또는 무채색
  • 게임용이면 one asset per sheet

3-2. 48~64px 검사

  • 축소했을 때 누군지 보이는가가 핵심
  • 실루엣, 주무기 위치, 방패 유무가 한눈에 보여야 함
  • 색만 다르고 모양이 같으면 실제 플레이에서 뭉개짐

3-3. 색보다 형태

  • 플레이어: 삼각형, 비대칭, 날렵함
  • 보안 적: 사각형, 대칭, 경직됨
  • 노드: 공통 육각 기단 + 중앙 장치
  • 보스: 움직이는 시설물처럼 크게

3-4. 프롬프트 필수어

  • top-down three-quarter view
  • transparent background
  • readable silhouette at 48–64 pixels
  • no text, no logo, no poster layout
  • concept sheet / sprite concept / minimap icon

4. 바이브 코딩식으로 게임 에셋 만드는 법

“그림부터 완벽하게 다 만들고 나중에 넣자”로 가면 오래 끈다. 바이브 코딩 쪽은 보통 빠른 프로토타입 → 빈칸 메우기 → 교체 반복이 맞다.

4-1. 1차는 ‘가짜 완성’으로 빨리

  1. 역할 고정: 플레이어인지, 원거리 적인지, 장판인지 먼저 정하기
  2. AI로 초안 3개: 한 대상당 3안 정도만 비교
  3. 앵커 1개 선택: 게임과 맞는 1안을 기준으로 확장
  4. 같은 톤으로 확장: 나머지 적·노드·무기를 이어서 제작
  5. 코드에 바로 넣기: 실제 크기에서 안 읽히면 탈락

4-2. 이름 규칙

assets/
  characters/
  enemies/
  bosses/
  nodes/
  weapons/
  vfx/
  ui/
  • 파일명은 영문 snake_case로 고정
  • 역할별 폴더를 먼저 나눠 코드 매칭을 단순화

4-3. 교체 가능한 임시본

  • 초안 에셋을 먼저 넣고 상위 버전으로 갈아끼우기
  • UI 아이콘, 투사체, 장판은 임시본으로도 테스트 가능
  • 보스·플레이어는 스타일 앵커, 잡몹은 템플릿화

4-4. 실제 스프라이트화

  • AI 이미지는 콘셉트 참조용으로 쓰고 Aseprite/Piskel에서 정리
  • 히트박스는 그림이 아니라 코드에서 관리
  • 장판·빔·경고선은 타격감보다 예고성 우선
  • 애니메이션은 처음부터 길게 말고 4~8프레임

5. 추천 툴 / 사이트

Aseprite

스프라이트 정리, 프레임 관리, 스프라이트 시트 출력에 강함.

Piskel

브라우저에서 바로 쓰는 무료 animated sprites & pixel art 에디터.

Kenney Assets

2D, 3D, UI, Audio, Pixel, Textures 등 프로토타입용 자산을 찾기 좋음.

OpenGameArt

에셋 라이브러리. CC0, CC-BY, CC-BY-SA 등 라이선스 확인 필수.

Godot / Phaser

스프라이트 시트, 애니메이션, 웹게임 적용 흐름을 확인하기 좋음.

OpenAI Image Guide

생성과 편집 흐름을 함께 활용해 한 번 뽑은 안을 계속 고쳐 쓰는 방식이 유리함.
